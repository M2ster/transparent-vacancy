# Прозрачная вакансия

CLI проверяет русскоязычные вакансии перед публикацией. Он загружает данные портала «Работа России» или открывает локальный JSON, применяет правила и просит локальную Ollama проверить смысл текста. Отчёт содержит замечания с цитатами и рекомендации редактору.

## Установка

Нужны Python 3.12, [uv](https://docs.astral.sh/uv/) и [Ollama](https://ollama.com/download). В Ubuntu установите Ollama по инструкции для Linux, запустите сервис и загрузите модель.

```bash
uv sync --locked
ollama pull qwen3:4b
```

По умолчанию CLI обращается к Ollama на `127.0.0.1:11434`. Облачный аккаунт не требуется.

## Запуск

```bash
# Регион 39, максимум 200 уникальных вакансий
uv run python -m vacancy_audit

# Все уникальные вакансии из файла, без запросов к порталу
uv run python -m vacancy_audit --input examples/synthetic_vacancies.json

# Короткая проверка двух страниц API и локальной модели
uv run python -m vacancy_audit --limit 2 --page-size 1 --num-ctx 6144 --output reports/smoke.json
```

По умолчанию отчёт записывается в `reports/latest.json`. `--output` меняет путь. Все доступные параметры перечислены в `--help`.

| Параметр | Значение по умолчанию |
| --- | --- |
| `--api-url` | API «Работа России», регион 39 |
| `--limit`, `--page-size` | 200 вакансий, до 100 на страницу |
| `--api-timeout` | 15 секунд |
| `--ollama-url`, `--model` | Локальная Ollama, `qwen3:4b` |
| `--num-ctx`, `--num-predict` | 4096 токенов контекста, до 900 токенов ответа |
| `--ollama-timeout` | 60 секунд на запрос |

Локальный JSON принимает `results.vacancies[].vacancy` либо массив вакансий. Повторы ID сохраняются по первой записи. API считает `offset` номером страницы с нуля. Некорректный вход или неудачный анализ завершаются с кодом 1. Предыдущий отчёт заменяется атомарно только после успешной проверки всех вакансий.

## Отчёт

Каждая вакансия представлена объектом `{id, url, issues}`. `url` равен `null`, если ссылки нет. `issues` может быть пустым. Замечание содержит тему `topic`, тип `type`, список доказательств `evidence`, проблему `problem` и рекомендацию `recommendation`. `evidence.field` — путь в исходной вакансии, например `addresses.address[0].location`. Цитаты проверяются по исходным значениям. Противоречие требует двух разных цитат, а полное отсутствие сведений допускает пустую цитату по отсутствующему полю. Пример реального запуска модели на синтетике находится в [examples/synthetic_report.json](examples/synthetic_report.json).

Правила ищут заполненность семи тем и проверяют числовые границы зарплаты. Ollama сопоставляет структурированные поля с текстом и добавляет смысловые замечания, например о конфликте удалённой работы с ежедневным присутствием в офисе. Модель может пропустить проблему или неверно истолковать исходный текст. Редактор проверяет рекомендации перед публикацией.

При ответе вне схемы или с неточными цитатами CLI запрашивает модель ещё раз. Повтор ограничивает цитаты точными выдержками из соответствующих исходных полей. При слишком длинном входе CLI завершает запуск с объяснением и предлагает увеличить `--num-ctx`, если хватает памяти. Оценка контекста консервативна и оставляет запас на шаблон разговора модели и ответ. При смене модели установите подходящие лимиты. Реальные выгрузки и отчёты могут содержать сведения из исходного объявления, поэтому храните их локально.

## Расписание и тесты

Пример [deploy/crontab](deploy/crontab) запускает команду ежедневно в 07:15 по системному времени. Скопируйте строку в `crontab -e` и при необходимости измените расписание. `flock` пропустит запуск, если предыдущий ещё работает. Для ручного запуска с той же блокировкой выполните из корня проекта:

```bash
flock -n .vacancy-audit.lock uv run --locked python -m vacancy_audit
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

Тесты используют подставные HTTP-ответы и работают без GPU и сети.

Источник данных — портал «Работа России», открытые данные Роструда. [Документация API](https://trudvsem.ru/opendata/api)
