# Прозрачная вакансия

CLI проверяет русскоязычные вакансии перед публикацией. Он загружает данные портала «Работа России» или открывает локальный JSON, применяет правила и просит локальную Ollama проверить смысл текста. Отчёт содержит замечания с цитатами и рекомендации редактору.

## Установка

Распакуйте проект и откройте терминал в его корне. Установите [uv](https://docs.astral.sh/uv/) и [Ollama](https://ollama.com/download). Запустите службу Ollama или выполните `ollama serve` в отдельном терминале, если служба ещё не работает.

```bash
uv python install 3.12
uv sync --locked
ollama pull qwen3:4b
```

По умолчанию CLI обращается к Ollama на `127.0.0.1:11434`. Облачный аккаунт не требуется.

## Запуск

Точка входа CLI — [src/vacancy_audit/__main__.py](src/vacancy_audit/__main__.py).

```bash
# Регион 39, максимум 200 уникальных вакансий
uv run --locked python -m vacancy_audit

# Все уникальные вакансии из файла, без запросов к порталу
uv run --locked python -m vacancy_audit --input examples/synthetic_vacancies.json

# Короткая проверка двух страниц API и локальной модели
uv run --locked python -m vacancy_audit --limit 2 --page-size 1 --output reports/smoke.json
```

По умолчанию отчёт записывается в `reports/latest.json`. `--output` меняет путь. Все доступные параметры перечислены в `--help`.

| Параметр | Значение по умолчанию |
| --- | --- |
| `--api-url` | API «Работа России», регион 39 |
| `--limit`, `--page-size` | 200 вакансий, до 100 на страницу |
| `--api-timeout` | 15 секунд |
| `--ollama-url`, `--model` | Локальная Ollama, `qwen3:4b` |
| `--num-ctx`, `--num-predict` | Автовыбор 6144, 8192 или 12288 токенов контекста для каждой вакансии, до 900 токенов ответа |
| `--ollama-timeout` | 60 секунд на запрос |

Локальный JSON принимает `results.vacancies[].vacancy` либо массив вакансий. Повторы ID сохраняются по первой записи. API считает `offset` номером страницы с нуля. Некорректный вход или неудачный анализ завершаются с кодом 1. Предыдущий отчёт заменяется атомарно только после успешной проверки всех вакансий.

Явный `--num-ctx 6144` фиксирует контекст всего запуска. Автовыбор берёт наименьший подходящий размер из 6144, 8192 и 12288. Оценка оставляет запас на шаблон разговора и ответ. RTX 4050 6 ГБ обработала длинную запись с `qwen3:4b` при 12288 токенах полностью на GPU. Если на другом устройстве не хватает памяти, используйте фиксированный бюджет, который оно поддерживает. При превышении лимита на любой записи CLI выводит оценку, прерывает весь запуск и сохраняет предыдущий отчёт.

## Интерфейс редактора

```bash
uv run --locked --group ui streamlit run app.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

Откройте `http://127.0.0.1:8501`. Сначала показывается демонстрационный отчёт. Загрузите `reports/latest.json` или другой отчёт CLI, чтобы просмотреть свои результаты. Сводка охватывает весь файл, а счётчик над списком показывает число найденных вакансий. Ищите по ID или названию и фильтруйте по наличию, теме и типу замечаний. Выбранные тема и тип должны совпасть в одном замечании. Раскройте строку вакансии, чтобы увидеть все её замечания, цитаты и рекомендации. Рекомендацию можно скопировать кнопкой в правом верхнем углу блока. Интерфейс читает готовый отчёт без обращения к модели.

## Отчёт

Каждая вакансия представлена объектом `{id, url, job_title, issues}`. `url` равен `null`, если ссылки нет. Необязательное поле `job_title` содержит название из исходного `job-name` или `null`. В старых отчётах без этого поля интерфейс показывает ID. `issues` может быть пустым. Замечание содержит тему `topic`, тип `type`, список доказательств `evidence`, проблему `problem` и рекомендацию `recommendation`. `evidence.field` — путь в исходной вакансии, например `addresses.address[0].location`. Цитаты проверяются по исходным значениям. Противоречие требует двух разных цитат, а полное отсутствие сведений допускает пустую цитату по отсутствующему полю. Пример реального запуска модели на синтетике находится в [examples/synthetic_report.json](examples/synthetic_report.json).

Правила проверяют структурированные поля семи тем, границы оплаты, достаточность графика и явные конфликты формата работы или стажа. Ollama сопоставляет структурированные поля с текстом и проверяет, есть ли сведения о теме в других полях. Редактор просматривает замечания перед публикацией, потому что модель может пропустить проблему или принять необязательную деталь за неоднозначность.

При ответе вне схемы или с неточными цитатами CLI запрашивает модель ещё раз. Для пропуска требуется пустая цитата и отсутствующее поле соответствующей темы. Если часть замечаний осталась неподтверждённой после повтора, CLI сохраняет подтверждённые и пишет предупреждение с ID вакансии в терминал или `.cron.log` при запуске по расписанию. Предупреждение означает, что JSON может содержать лишь часть замечаний. Если после невалидного вывода не подтверждено ни одного замечания, запуск завершается с ошибкой и предыдущий отчёт остаётся на месте. Реальные выгрузки и отчёты могут содержать сведения из исходного объявления, поэтому храните их локально.

## Расписание и тесты

В [deploy/crontab](deploy/crontab) указан ежедневный запуск в 07:15 по системному времени. Перед установкой через `crontab -e` проверьте каталог проекта и абсолютный путь к `uv` командой `command -v uv`. При необходимости добавьте `--api-url URL --limit N` после `vacancy_audit` и перед перенаправлением вывода. `flock` пропускает запуск, если предыдущий ещё работает. Вывод добавляется в `.cron.log`. Та же команда вручную из корня проекта:

```bash
/usr/bin/flock -n .vacancy-audit.lock "$HOME/.local/bin/uv" run --locked python -m vacancy_audit
```

Тесты используют подставные HTTP-ответы и работают без GPU и сети после установки зависимостей.

```bash
uv run --locked --group ui pytest
uv run --locked ruff check .
uv run --locked ruff format --check .
uv lock --check
```

## Демонстрация до трёх минут

1. **0:00–0:30.** Покажите, откуда берутся вакансии. Запустите короткую команду API с двумя страницами из раздела «Запуск». Заранее загрузите модель и откройте интерфейс.
2. **0:30–1:40.** Пока Ollama обрабатывает данные, откройте демонстрационный отчёт. Найдите `office-conflict` и покажите две исходные цитаты. В `shift-needs-detail` покажите, какие сведения о сменах предлагает уточнить редактор.
3. **1:40–3:00.** Загрузите созданный `reports/smoke.json`, покажите сводку и раскройте строку вакансии. Если API задерживается, продолжите на демонстрационном отчёте и покажите результат реального запроса после завершения.
